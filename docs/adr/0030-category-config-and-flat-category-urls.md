# 0030. Category config and flat category URLs

Status: Accepted
Date: 2026-09-20

## Context

The site has eleven tool categories. They appear in the design system (accent colors), on the home page, in the header menu and the footer, on the all-tools page, and as pages of their own. ADR 0014 puts every tool at `/<tool-id>` and says reserved paths are checked at build time, without saying which paths are reserved. Category pages need URLs that are short, keyword-rich and stable.

## Decision

### One config

`apps/web/src/config/categories.ts` is the single source for the categories. Each has:

| Field | Meaning |
|---|---|
| `id` | Short id. Matches the `--cat-*` color token and the `data-cat` attribute (`pdf`, `video-audio`, ...). |
| `name` | Display name, also the H1 and the page title ("PDF tools", "Calculators"). |
| `slug` | URL segment (`pdf-tools`). |
| `description` | One line, for tiles and lists. |
| `accent` | The category color token (`cat-pdf`), used only as the tint of the small icon chip (ADR 0028). |
| `icon` | Icon name from the design system. |
| `intro` | Two to three sentences for the category page, unique per category. |
| `metaDescription` | The category page's meta description, under 160 characters. |

Pages and components read this list; none of them repeat a name, slug or description. The tool registry (Mission 8) builds on it. The file moved here from `src/data/categories.ts`, and `label` is now `name`.

### Flat URLs

Category pages live at the site root, with the tool URLs of ADR 0014: `/pdf-tools/`, `/image-tools/`, `/video-audio-tools/`, `/text-tools/`, `/calculators/`, `/converters/`, `/generators/`, `/developer-tools/`, `/web-seo-tools/`, `/color-design-tools/`, `/date-time-tools/`. `/tools/` lists all tools.

URLs always end in a slash (`trailingSlash: "always"` in `astro.config.mjs`), so dev, build and every link agree on one form and no internal link needs a redirect. Cloudflare redirects the slashless form.

### Reserved paths

The category slugs and the static page paths (`tools`, `about`, `contact`, `privacy`, `terms`, `design-system`, `404`) are reserved: no tool id may use them. `config/categories.ts` exports them as `reservedPaths`, and Mission 8's registry validator must enforce the rule. Two tests guard the list today: `site.test.ts` fails if `staticPagePaths` and the files in `src/pages` disagree, and `categories.test.ts` fails if a slug collides with a static page.

### Category pages

Generated by `src/pages/[category].astro` with `getStaticPaths`. Until tools exist each page shows an honest empty state; a tile with no tools says "Coming soon" and never a number.

## Consequences

- Adding a category is one entry in one file, plus its color token and icon (the tests check both).
- Keyword-rich flat URLs are good for search, but every slug is a permanent claim on a top-level path, so slugs must not be renamed casually (renames go through the redirects registry of ADR 0014).
- Astro cannot have two dynamic routes at the same level, and tools also live at `/<tool-id>`. Mission 8 must merge `[category].astro` and the tool route into one route module that resolves a path to a category or a tool.

## Revisit when

Categories are added, removed or renamed, or when the number of categories makes the flat namespace hard to keep collision-free.
