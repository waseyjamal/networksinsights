# 0044. AEO (answer engine optimisation)

Status: Accepted
Date: 2026-09-21

## Context

Assistants that answer questions (ChatGPT, Claude, Perplexity, Google's AI features) quote short, self-contained statements, and they favour pages that state the answer first and state facts plainly. The owner's priority is to be the source such an assistant quotes for "what does this tool do" and "is it free". Google's own guide (May 2026) says no special markup or file is needed for its AI features, so this ADR is about writing and data, not tricks. The rule that governs everything here is AGENTS.md's: never invent content, counts, ratings or claims.

## Decision

**A. Quick facts on every tool page.** A visible definition list (`FactList`, a design-system component, ADR 0028) under the workspace, built only from the manifest by `quickFacts()` in the SDK:

| Fact | Value |
|---|---|
| Price | Free (every tool on the site is free) |
| Sign-up | Not required |
| Where it runs | On your device (client, worker) or On our server, from `runtime` |
| Files uploaded | No (client, worker) or Yes (server), from `runtime`, the same source as the privacy sentence (ADR 0034) |
| Limits | From `manifest.limits`, or "No fixed limit" |
| Accepts, Produces | From the new optional manifest fields `accepts` and `produces`; shown only when present |
| Updated | `manifest.updated`, as a `<time>` |

Nobody types a fact: a page cannot say a file stays on the device when the runtime sends it to us, or claim a limit that is not enforced (ADR 0015). `accepts` and `produces` are lists of one to twelve file formats, named as a reader names them (`PDF`, `JPG`, `H.264`, `Plain text`), no repeats; `pnpm new:tool` takes `--accepts` and `--produces`. Where schema.org has a matching property the fact also feeds the structured data (the price as a free `offers`, the date as `dateModified`); it has none for the others (ADR 0039). The visible-value test covers all of it.

**B. Answer-first gate.** Two content quality gates (ADR 0036):
- `answer-first` (a failure): the first sentence of the intro has at most 30 words, so the answer comes before anything else. It fails the build and `pnpm check:tools`.
- `answer-first-name` (a warning): the first sentence names the tool, so the sentence stands on its own when it is quoted away from the page. It is printed by `check:tools` and by the build and never fails anything; a good sentence sometimes reads better without the name.
The gates have passing and failing fixtures like every gate. A gate can now have severity `warning`; `check:tools` shows it with `!` and lists it apart from the problems.

**C. Writing rules** (`docs/adding-a-tool.md`, "AEO rules"): answer first, FAQs phrased as the questions a person really types, facts only from data, no invented claims.

## Consequences

- Every tool page states its price, privacy and limits in the same words, in a form a machine can lift.
- The generator's intro stub and the prompt template teach the rule, so a tool written by an agent starts right.
- Only `accepts` and `produces` are new authoring work; the other facts cost nothing.
- A tool whose limits are added later gets them shown automatically.

## Revisit when

An assistant vendor documents what it prefers to quote, or a fact needs a source that is not the manifest.
